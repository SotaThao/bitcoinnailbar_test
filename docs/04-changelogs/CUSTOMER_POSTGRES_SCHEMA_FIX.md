## 🚨 Problem

Booking system failures due to **TWO separate schema issues**:

### Error 1: Missing Column
```
Could not find the 'last_visit' column of 'customer_profiles' in the schema cache
```
**Root Cause:** Code used `last_visit` but actual column name is `last_visit_date`

### Error 2: NULL ID Constraint Violation
```
null value in column "id" of relation "customer_profiles" violates not-null constraint
Failing row contains (null, testmerchant@mailinator.com, 5555555559, Jane, ...)
```
**Root Cause #2:** Postgres table `customer_profiles` missing `DEFAULT gen_random_uuid()` for `id` column

### 2. Fixed NULL ID Constraint - UUID Workaround

**Root Issue:** Postgres table missing `DEFAULT gen_random_uuid()` on `id` column

**Workaround:** Generate UUID in application code before insert

**Files Modified:**
- `/supabase/functions/server/index.tsx` (Line 700)
- `/supabase/functions/server/customers_booking_postgres.tsx` (Line 192)
- `/supabase/functions/server/customers_postgres.tsx` (Line 206)

**Pattern Applied:**
```typescript

const customerId = crypto.randomUUID();

const { data: newCustomer, error: insertError } = await supabase
  .from('customer_profiles')
  .insert({
    id: customerId,  // ✅ Explicitly provide UUID
    phone: normalizedPhone,
    // ...
  })
  .select()
  .single();
```

**Permanent Fix Recommended:**
```sql
-- Run in Supabase SQL Editor to enable auto-generation
ALTER TABLE customer_profiles 
ALTER COLUMN id SET DEFAULT gen_random_uuid();
```

See `/docs/03-guides/POSTGRES_SCHEMA_FIX_UUID.md` for detailed migration guide.

## 🔍 Technical Details

### Why Manual ID Failed

1. **Postgres Constraints:**
   - `id` column has `NOT NULL` constraint
   - Expected to be auto-generated by DB (UUID or SERIAL)
   
2. **Old KV Store Pattern:**
   - KV store allowed custom IDs like `customer_us:1234567890`
   - Postgres requires UUID or auto-increment integers
   
3. **Proper Pattern:**
   ```typescript
   // ❌ DON'T: Manual ID
   .insert({ id: 'custom-id', ... })
   
   // ✅ DO: Let DB generate ID
   const { data } = await supabase
     .from('customer_profiles')
     .insert({ phone, email, ... })
     .select()
     .single();
   // Access auto-generated ID: data.id
   ```

### Column Name Verification

From `customers_postgres.tsx` Line 73:
```typescript
function transformCustomerResponse(customer: any) {
  return {
    // ...
    last_visit: customer.last_visit_date,  // ✅ Maps last_visit_date → last_visit
  };
}
```

This confirms:
- **Database column:** `last_visit_date`
- **API response field:** `last_visit` (transformed for backwards compatibility)
- **Insert/Update operations:** Must use `last_visit_date`

## 🎓 Lessons Learned

1. **Always Check Schema First**
   - Don't assume column names
   - Verify with existing CRUD modules
   - Use `.describe()` or schema documentation

2. **Let DB Handle IDs**
   - Never manually assign IDs in Postgres
   - Use `.select().single()` to retrieve generated IDs
   - UUIDs/Serials are DB-managed

3. **Column Name Consistency**
   - API responses can transform names
   - DB operations must use actual column names
   - Check `transformResponse()` functions for mappings

4. **Migration Strategy**
   - KV Store → Postgres migration requires pattern changes
   - Custom IDs → Auto-generated IDs
   - Document schema differences clearly
