## 📝 **FILES CHANGED:**

### **1. NEW FILE: `/supabase/functions/server/services.tsx`**

**Lines:** 106 lines  
**Routes:** 3 routes

| Route | Method | Description | Special Logic |
|-------|--------|-------------|---------------|
| `/services` | GET | List all services | ✅ Booking count enrichment |
| `/services` | POST | Create new service | Standard CRUD |
| `/services/:id` | DELETE | Delete service by ID | Direct Supabase delete |

**Dependencies:**
- `_shared_kv.tsx` → `kvAdmin` (admin KV table)
- `_shared_supabase_client.tsx` → Direct Supabase client for DELETE
- `_shared_constants.tsx` → `KV_TABLE_ADMIN`

**Business Logic (GET):**
1. Fetch all services with prefix `service:`
2. Fetch all appointments to calculate booking count
3. Count how many times each service appears in appointments
4. Enrich each service with:
   - `bookingCount`: Number of times service was booked
   - `isOwnerRecommended`: Boolean from `owner_recommended` field
5. Sort services by `bookingCount` (descending - most popular first)

**KV Storage:**
- Table: `kv_store_89edbd69` (admin)
- Prefix: `service:`
- Example ID: `service:1737745400000`

**Note:** Currently services use admin table, but according to Guidelines.md they should eventually migrate to homepage table (`kv_store_84f9c112`). This is intentionally deferred to avoid mixing concerns.
